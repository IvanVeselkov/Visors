# 02. Архитектура

## 1. Блок-схема

```
                    ┌─────────────────────────────────────────┐
                    │                ESP32 (3.3 В)             │
  OV7670            │                                          │
 ┌────────┐  D0–D7  │  I2S0 parallel  ──►  кадровый буфер      │
 │ сенсор │─8 бит──►│  (DMA)              128×128 grayscale    │
 │ +LDO   │  PCLK   │       │                    │             │
 │        │  VSYNC  │       ▼                    ▼             │
 │        │  HREF   │  SCCB (I2C)        обработка: gamma,      │
 │        │◄─SIOD───│  настройка         контраст, зум, OSD     │
 │        │──SIOC──►│  экспозиция/усил.          │             │
 │        │◄─XCLK───│  8–10 МГц                  ▼             │
 └────────┘         │                     SPI 40 МГц ────► ST7735 128×128
                    │                                          │
                    │  LEDC PWM ──► MOSFET ──► ИК 850 нм       │
                    │  GPIO ──────► кнопки (режим, зум, ИК)    │
                    └─────────────────────────────────────────┘
                                    ▲
                              1S Li-Ion ──► 5 В boost ──► VIN
```

## 2. Почему ESP32, а не Nano

| Требование | Nano (ATmega328P) | ESP32 |
|---|---|---|
| Кадр 128×128 RGB565 | 32 КБ (RAM 2 КБ) — невозможно | 32 КБ из 520 КБ — легко |
| Приём 8-бит потока | программный polling, ~1–2 МГц предел | I2S + DMA, десятки МГц |
| Вывод 32 КБ на SPI | ~2–3 с на кадр | ~7 мс на 40 МГц |
| Обработка (gamma, зум) | нет запаса | 240 МГц × 2 ядра |

Nano остаётся в проекте только как вспомогательный контроллер, если
понадобится разгрузить ESP32 по кнопкам/питанию. В базовой версии он не нужен.

## 3. Схема соединений

### 3.1 Камера → ESP32

У классического ESP32 камера работает через I2S0 parallel, и пины данных
**фиксированы** (это распиновка референсной ESP32-CAM / esp32-camera).
Менять их произвольно нельзя — в отличие от ESP32-S3.

| Сигнал OV7670 | GPIO ESP32 | Примечание |
|---|---|---|
| D0 | 5 | strapping, но как вход данных — ок |
| D1 | 18 | |
| D2 | 19 | |
| D3 | 21 | |
| D4 | 36 | input-only |
| D5 | 39 | input-only |
| D6 | 34 | input-only |
| D7 | 35 | input-only |
| PCLK | 22 | |
| VSYNC | 25 | |
| HREF | 23 | |
| XCLK | 0 | выход LEDC 8–10 МГц, 50 % |
| SIOD (SDA) | 26 | SCCB, подтяжка 4.7 кОм к 3.3 В |
| SIOC (SCL) | 27 | SCCB, подтяжка 4.7 кОм к 3.3 В |
| PWDN | GND | или на GPIO, если нужен сон камеры |
| RESET | 3.3 В через 10 кОм | |
| 3V3 / GND | 3.3 В / GND | |

> Проверить на своём модуле: часть плат имеет отдельный пин `2.8V`/`VCC`.
> Питать сенсор 5 В нельзя. Модуль 18-пиновый, **без FIFO** — значит XCLK
> должен идти непрерывно, а приём — строго через DMA (I2S). Программный
> polling на ESP32 тоже даст рваный кадр.

**Программная база:** компонент `esp32-camera` (espressif/esp32-camera)
поддерживает OV7670, но хуже, чем OV2640: нет JPEG, часть регистров
настраивается вручную. Если картинка нестабильна — правим инициализацию
(COM7/COM3, CLKRC, делители PLL) или берём готовый драйвер под OV7670.
Пины задаются через `camera_config_t` (значения из таблицы выше).

### 3.2 Дисплей → ESP32

| Сигнал | GPIO ESP32 | Примечание |
|---|---|---|
| SCK | 14 | SPI, до 40 МГц |
| MOSI | 13 | |
| CS | 15 | strapping, подтянут — ок |
| DC | 2 | strapping, не мешает (выход) |
| RST | 4 | |
| BL | 32 | LEDC PWM для яркости |
| VCC / GND | 3.3 В / GND | |

MISO у модуля нет (8 пинов, SPI только на запись) — читать ID контроллера
нельзя, драйвер определяется перебором конфигураций.

Свободными остаются GPIO 12, 16, 17, 33 — их хватает на 3 кнопки + управление ИК.

### 3.3 Периферия

| Узел | Пин | Схема |
|---|---|---|
| ИК-подсветка (PWM) | 12 | GPIO → 100 Ом → затвор AO3400/IRLZ44N, 10 кОм затвор–GND, исток–GND, сток → светодиоды → +5 В |
| Кнопка «режим» | 16 | GPIO → кнопка → GND, внутренняя подтяжка вверх |
| Кнопка «зум» | 17 | то же |
| Кнопка «ИК» | 33 | то же |

### 3.4 Питание

```
1S Li-Ion 3.7 В ──► защита/заряд (TP4056) ──► boost 5 В ──► VIN ESP32
                                                    │
                                                    ├──► ИК-светодиоды (через MOSFET)
                                                    └──► 3.3 В LDO на модуле ESP32

Питание камеры и дисплея — с пина 3V3 платы ESP32 (они маломощные).
```

Почему не 1S напрямую на `3V3`: линейный стабилизатор на DevKit требует
≥4.6–4.8 В на входе, иначе просадка. Почему не 2S: лишний вес и КПД.
Рабочий вариант — 1S + повышайка 5 В, либо 2S + понижайка (лучше по КПД
и стабильности, но тяжелее).

**Бюджет тока:** ESP32 120 мА + камера 80 мА + дисплей 25 мА + подсветка
300–1000 мА. Средний ток ~0.6–1.2 А → 18650 3000 мА·ч даёт ~2–3 часа
с включённой подсветкой и ~5–6 часов без неё.

## 4. Тракт изображения

```
1. Захват          QQVGA 160×120, YUV422 (ночь) или RGB565 (день)
2. Буферизация     целиком в SRAM (нет tearing) — 16–38 КБ
3. Кроп/скейл      центр 128×120 + паддинг, либо линейный ресайз до 128×128
4. Яркость         для YUV422 берём Y-плоскость — 0 затрат на конвертацию
5. Кривая          LUT 256→256: gamma + подъём теней + клиппинг шумов
6. Упаковка        Y → RGB565 (r=g=b) для ST7735
7. Вывод           SPI DMA, окно 128×128
```

### Почему YUV422, а не RGB565

OV7670 в YUV422 отдаёт Y (яркость) на каждый пиксель, а U/V — через один.
Для ночного визора нужна именно яркость, поэтому конвертация RGB→Y
не нужна вообще: читаем каждый второй байт. В цветном режиме — RGB565
с BE-порядком байт (частая причина «зелёной» картинки).

### Бюджет кадра (цель 25–30 FPS)

| Операция | Время (оценка) |
|---|---|
| Захват QQVGA @ 30 FPS | 33 мс (ограничение камеры) |
| Выборка Y + LUT 128×128 | ~1 мс |
| Упаковка в RGB565 | ~1 мс |
| SPI 32 КБ @ 40 МГц | ~7 мс |
| **Итого** | **~35–40 мс → 25–28 FPS** |

Узкое место — не ESP32 и не SPI, а сама камера и выдержка в темноте.
В темноте AEC увеличивает экспозицию, и FPS падает до 5–15 — это нормально
и для NV приемлемо.

### «Параллельный» вывод: что реально возможно

Экран у нас **последовательный (SPI)** — параллельной шины у него нет,
и это не ограничение: 32 КБ кадра уходят за ~7 мс, быстрее, чем камера
успевает снять следующий.

Параллелизм делается на другом уровне — **конвейер**:

```
ядро/периферия:  камера(DMA) ──► буфер A ──┐
                                            ├──► CPU: Y->LUT->RGB565 ──► SPI ──► экран
ядро/периферия:  камера(DMA) ──► буфер B ──┘
```

Камера заполняет второй буфер, пока первый преобразуется и выводится.
На ESP32 это делает сам драйвер (`fb_count = 2`, `CAMERA_GRAB_LATEST`):
`esp_camera_fb_get()` отдаёт уже готовый кадр, а DMA в это время пишет
следующий. Отдельные задачи/ядра не нужны, задержка не растёт.

Итоговая задержка: экспозиция (до 33 мс) + преобразование (2 мс) +
SPI (7 мс) + инерция ЖК (~15 мс) ≈ **60–90 мс**.
Режим «параллельного» вывода реализован в `firmware/live_view`.

### Задержка

Сквозная задержка складывается из экспозиции (до 33 мс) + обработки (2 мс) +
вывода (7 мс) + инерции ЖК (~15 мс) ≈ **60–90 мс**. Для страйкбола приемлемо,
но целиться «в движении» будет непривычно.

## 5. Ночной режим

* **Снять ИК-фильтр** с объектива (или купить объектив без фильтра).
  Без этого 850 нм почти не проходит.
* **Подсветка 850 нм.** 850 нм слабее греет матрицу и дешевле, но даёт
  слабый красный «зайчик»; 940 нм незаметнее, но нужно в 3–4 раза больше
  мощности. Для страйкбола 850 нм — практичный выбор.
* **Управление экспозицией/усилением** через SCCB: фиксируем AEC/AGC,
  чтобы картинка не «дышала», и даём кнопкам ручную регулировку.
* **Кривая яркости:** ночью почти всегда нужен подъём теней + шумоподавление.
  Простое решение — LUT и медианный фильтр 3×3 на 128×128 (дёшево по CPU).
* **Без подсветки** OV7670 при звёздном свете даёт шумное, малоконтрастное
  изображение. Это активный ИК-визор, а не пассивный «starlight».

## 6. Оптика и механика

* Экран 1.44" (36.5 мм по диагонали), линза плоско-выпуклая f = 40–60 мм,
  диаметр 25–30 мм.
* Линза ставится на расстоянии f от экрана — тогда глаз видит изображение
  «на бесконечности» и не устаёт. Увеличение ≈ 2–2.5×, угловое поле
  ≈ 35–45° по диагонали.
* Регулировка: подвижка экрана ±5 мм по фокусу + межзрачковое расстояние,
  если делаем бинокуляр.
* Корпус: PETG/ABS печать или коробка + крепление на шлем (M-LOK/velcro).
  На первом этапе — фанерный/картонный макет, чтобы поймать геометрию.
* Масса цели: < 300 г с аккумулятором.

## 7. Варианты архитектуры

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **A. ESP32 + OV7670 без FIFO** | всё уже есть, 25 FPS, обработка на месте | фиксированные пины, чувствительность к проводам, нет буфера кадра | **выбран** |
| B. ESP32 + OV7670 с FIFO | прощает тайминги, можно медленный MCU | FIFO — узкое место по скорости, лишние пины | покупка, только если A не заведётся |
| C. Nano + OV7670 FIFO | «по-простому» | 1–2 FPS, нет обработки | не планируется |
| D. ESP32-S3 + OV2640/OV5640 | LCD_CAM, PSRAM, JPEG, USB | нужно докупать | путь апгрейда |
| E. Аналоговая камера + LCD-модуль | дёшево, 0 кода | нет обработки, нет записи | не наш путь |

> **Подтверждено:** имеющийся модуль — 18-пиновый **без FIFO**. Варианты B и C
> требуют покупки другого модуля и остаются только планом Б. Работаем по A.
